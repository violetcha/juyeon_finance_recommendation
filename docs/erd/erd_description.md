# ERD 설계 설명

본 프로젝트의 ERD는 Django `models.py`를 기반으로 작성한 데이터베이스 설계도이다.
서비스에서 저장·관리하는 사용자, 프로필, 은행, 예적금 상품, 금리 옵션, 관심상품, 주거래은행 성향 진단 결과, 커뮤니티, 댓글, 저장 영상 데이터의 관계를 표현하였다.

또한 전체 ERD를 한 장으로만 첨부할 경우 테이블 수와 관계선이 많아 가독성이 떨어질 수 있으므로, 전체 구조를 확인할 수 있는 `erd_full`과 핵심 기능 중심의 `erd_core`, 부가 기능 중심의 `erd_sub`로 나누어 첨부하였다.

실제 Django 프로젝트에서는 앱 이름이 포함된 물리 테이블명이 사용되지만, 문서용 ERD에서는 서비스 구조를 쉽게 이해할 수 있도록 도메인 기준의 논리 테이블명으로 간소화하였다.

## ERD 파일 구성

* `erd_full.png`: 프로젝트 전체 데이터베이스 구조를 요약한 전체 개요 ERD
* `erd_core.png`: 회원 프로필, 예적금 상품 조회, 관심상품, 주거래은행 성향 진단 등 핵심 기능 중심 ERD
* `erd_sub.png`: 커뮤니티, 댓글, 좋아요, 저장 영상 등 부가 기능 중심 ERD

## ERD 관계 표시 기준

ERD의 관계선에 표시된 기호는 각 테이블 간 데이터 개수 관계를 의미한다.

| 표시     | 의미                  |
| ------ | ------------------- |
| `1`    | 반드시 하나의 데이터와 연결됨    |
| `0..1` | 없거나 하나의 데이터와 연결됨    |
| `*`    | 여러 개의 데이터와 연결될 수 있음 |

예를 들어 `Bank 1 - * FinancialProduct` 관계는 하나의 은행이 여러 개의 예금·적금 상품을 가질 수 있음을 의미한다.

## 주요 테이블

* `User`: 회원의 기본 인증 정보
* `UserProfile`: 금융상품 추천에 필요한 사용자 추가 정보
* `Bank`: 은행 정보
* `FinancialProduct`: 예금·적금 상품 기본 정보
* `ProductOption`: 상품별 가입 기간 및 금리 옵션
* `FavoriteProduct`: 사용자의 관심 예적금 상품
* `BankTestResult`: 주거래은행 성향 진단 결과
* `Post`: 커뮤니티 게시글
* `Comment`: 게시글 댓글
* `PostLike`: 게시글 좋아요 정보
* `CommentLike`: 댓글 좋아요 정보
* `SavedVideo`: 사용자가 저장한 금융 관련 YouTube 영상 정보

## 핵심 관계

* 사용자 한 명은 하나의 프로필 정보를 가진다.
* 하나의 은행은 여러 예금·적금 상품을 가진다.
* 하나의 예금·적금 상품은 여러 가입 기간 및 금리 옵션을 가진다.
* 사용자는 여러 예금·적금 상품을 관심상품으로 저장할 수 있다.
* 사용자는 여러 번 주거래은행 성향 진단을 진행할 수 있다.
* 주거래은행 성향 진단 결과는 추천된 은행 정보와 연결될 수 있다.
* 사용자는 여러 개의 커뮤니티 게시글을 작성할 수 있다.
* 하나의 게시글은 여러 개의 댓글을 가질 수 있다.
* 사용자는 게시글과 댓글에 좋아요를 남길 수 있다.
* 사용자는 금융 관련 YouTube 영상을 저장하고 마이페이지에서 다시 확인할 수 있다.

## 주요 관계 해석

### User - UserProfile

사용자 한 명은 하나의 프로필 정보를 가진다.

* 관계: `User 1 - 1 UserProfile`
* 의미: 회원가입한 사용자는 마이페이지에서 금융상품 추천에 필요한 프로필 정보를 관리할 수 있다.
* 프로필에는 나이, 성별, 월 소득 구간, 월 저축 가능 금액, 보유 목돈, 주거래은행, 주소, 개인정보 활용 동의 여부가 저장된다.

### Bank - FinancialProduct

은행 하나는 여러 개의 예금·적금 상품을 가질 수 있다.

* 관계: `Bank 1 - * FinancialProduct`
* 의미: 국민은행, 신한은행, 하나은행 등 하나의 은행은 여러 금융상품을 제공할 수 있다.

### FinancialProduct - ProductOption

예금·적금 상품 하나는 여러 개의 금리 옵션을 가질 수 있다.

* 관계: `FinancialProduct 1 - * ProductOption`
* 의미: 하나의 상품은 6개월, 12개월, 24개월 등 가입 기간별 금리 정보를 가질 수 있다.
* 상품 기본 정보와 기간별 금리 정보를 분리하여 상품 조회와 옵션 비교가 가능하도록 설계하였다.

### User - FavoriteProduct - FinancialProduct

사용자는 여러 금융상품을 관심상품으로 저장할 수 있다.

* 관계: `User 1 - * FavoriteProduct`
* 관계: `FinancialProduct 1 - * FavoriteProduct`
* 의미: `FavoriteProduct`는 사용자와 금융상품 사이의 연결 테이블 역할을 한다.
* 동일한 사용자가 같은 상품을 중복 저장하지 않도록 사용자와 상품 조합을 고유하게 관리한다.

### User - BankTestResult - Bank

사용자는 여러 번 주거래은행 성향 진단을 진행할 수 있으며, 각 진단 결과는 추천 은행과 연결될 수 있다.

* 관계: `User 1 - * BankTestResult`
* 관계: `Bank 0..1 - * BankTestResult`
* 의미: 하나의 진단 결과는 추천 은행이 없거나 하나만 가질 수 있고, 하나의 은행은 여러 사용자에게 추천될 수 있다.
* 진단 결과에는 접근성 선호, 혜택 선호, 안정성 선호, 이용 목적, 추천 사유를 저장한다.

### User - Post

사용자 한 명은 여러 개의 게시글을 작성할 수 있다.

* 관계: `User 1 - * Post`
* 의미: 사용자는 커뮤니티에서 자유글, 상품 후기, 금융 팁 등의 게시글을 작성할 수 있다.

### Post - Comment

게시글 하나는 여러 개의 댓글을 가질 수 있다.

* 관계: `Post 1 - * Comment`
* 의미: 하나의 게시글에 여러 댓글이 작성될 수 있으며, 댓글은 작성자와 게시글 정보를 함께 참조한다.

### Post - PostLike - User

사용자는 여러 게시글에 좋아요를 남길 수 있고, 하나의 게시글은 여러 사용자의 좋아요를 받을 수 있다.

* 관계: `Post 1 - * PostLike`
* 관계: `User 1 - * PostLike`
* 의미: `PostLike`는 게시글과 사용자 사이의 좋아요 관계를 저장하는 중간 테이블 역할을 한다.

### Comment - CommentLike - User

사용자는 여러 댓글에 좋아요를 남길 수 있고, 하나의 댓글은 여러 사용자의 좋아요를 받을 수 있다.

* 관계: `Comment 1 - * CommentLike`
* 관계: `User 1 - * CommentLike`
* 의미: `CommentLike`는 댓글과 사용자 사이의 좋아요 관계를 저장하는 중간 테이블 역할을 한다.

### User - SavedVideo

사용자는 여러 개의 금융 관련 YouTube 영상을 저장할 수 있다.

* 관계: `User 1 - * SavedVideo`
* 의미: 사용자는 주거래은행 추천 또는 금융상품 이해에 도움이 되는 YouTube 영상을 저장하고 마이페이지에서 다시 확인할 수 있다.

## 설계 의도

예적금 상품은 하나의 상품에 여러 가입 기간과 금리 조건이 존재할 수 있으므로, 상품 기본 정보는 `FinancialProduct`에 저장하고 기간별 금리 정보는 `ProductOption`으로 분리하였다. 이를 통해 하나의 상품에 대해 여러 기간별 금리 옵션을 효율적으로 관리할 수 있다.

사용자 금융 정보는 Django 기본 `User` 모델에 직접 저장하지 않고 `UserProfile` 모델로 분리하였다. `User`는 로그인과 인증에 필요한 기본 정보를 담당하고, `UserProfile`은 금융상품 추천에 필요한 나이, 성별, 월 소득 구간, 월 저축 가능 금액, 보유 목돈, 주거래은행, 주소 정보를 관리하도록 설계하였다.

관심상품 기능은 사용자와 금융상품 사이의 다대다 관계를 표현하기 위해 `FavoriteProduct` 테이블로 분리하였다. 이를 통해 사용자는 여러 상품을 저장할 수 있고, 하나의 상품도 여러 사용자에게 관심상품으로 등록될 수 있다.

주거래은행 성향 진단 기능은 사용자의 금융 이용 성향을 분석하여 적합한 은행을 추천하는 기능이므로, 진단 결과와 추천 은행 정보를 `BankTestResult` 테이블에 저장하도록 설계하였다.

커뮤니티 기능은 게시글과 댓글을 분리하여 하나의 게시글에 여러 댓글이 연결될 수 있도록 설계하였다. 또한 게시글 좋아요와 댓글 좋아요는 각각 `PostLike`, `CommentLike` 테이블로 분리하여 사용자별 좋아요 여부를 관리할 수 있도록 하였다.

YouTube 영상 저장 기능은 사용자가 금융 관련 영상을 다시 확인할 수 있도록 `SavedVideo` 테이블로 분리하였다. 영상 ID, 제목, 채널명, 썸네일 URL 등을 저장하여 마이페이지에서 저장한 영상 목록을 제공할 수 있다.

환율 계산기, 지도 검색, 금 시세 조회, AI 챗봇 기능은 외부 API 응답을 조회하여 화면에 제공하는 구조이다. 현재 구현 기준으로 별도 저장 모델을 두지 않으므로 ERD에는 독립 테이블로 포함하지 않았다.
